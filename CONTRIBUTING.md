# Contributing to ROS

## Branch strategy

- `main` is protected and releasable.
- Work is performed on `agent/*`, `feature/*`, `fix/*`, or `docs/*` branches.
- Every change enters through a pull request.

## Pull request requirements

- one coherent objective;
- acceptance criteria linked to an issue;
- tests for domain behavior;
- security and privacy impact noted;
- audit implications documented;
- no secrets or production data;
- architecture decision record when a durable technical choice changes.

## Definition of Done

A change is complete only when code review, automated checks, relevant tests, documentation, observability and acceptance criteria are complete.
